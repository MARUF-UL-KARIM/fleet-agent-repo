# GitHub Actions Android APK Build Guide

This document provides instructions for building and downloading the Android APK for **fleet-agent** directly on GitHub's cloud infrastructure using GitHub Actions in a web browser.

---

## 1. Project Architecture Overview

- **Kotlin Android Client (~80%)**: The Android application (`com.fleet.agent`) located in the `app/` directory handles Android foreground services, screen captures, SMS telemetry, and MQTT communication.
- **Python Relay Server (~20%)**: `bot.py` is a Telegram bot and Flask web application that acts as an external relay server.
- **Integration Mechanism**: The Kotlin Android app and Python relay server communicate asynchronously over MQTT messaging (`broker.hivemq.com`). Python is hosted on a cloud backend server (such as Render) and does not need to be compiled inside the Android APK.

## 3. How to Trigger the Cloud Build on GitHub.com

No local installation of Android Studio, JDK, SDK, or Gradle is required. You can trigger the entire build process using any web browser on GitHub.com:

1. Open your repository on GitHub.com in your web browser:
   `https://github.com/MARUF-UL-KARIM/fleet-agent-repo`
2. Click on the **Actions** tab near the top of the repository page.
3. In the left sidebar under "All workflows", select **Build Android APK**.
4. Click the **Run workflow** dropdown menu on the right.
5. Select the branch (e.g. `main`) and click the green **Run workflow** button.
6. The workflow will appear in the run history list. Click on it to monitor real-time build progress and logs.

---

## 4. How to Download the Generated APK

1. Once the workflow run finishes successfully (indicated by a green checkmark):
2. Click on the completed workflow run title (e.g., `Build Android Debug APK`).
3. Scroll down to the **Artifacts** section at the bottom of the summary page.
4. Click on **android-apk** to download a ZIP archive containing `app-debug.apk`.
5. Extract the ZIP file and install `app-debug.apk` on a compatible Android device running Android 8.0 (API 26) or higher.

---

## 5. Security and CI Configuration Notes

- **Repository Permissions**: The workflow runs with `contents: read` permissions.
- **Signing**: The build produces a debug APK signed with the standard Android debug keystore automatically generated by Gradle.
- **Dependencies Init Script**: The CI pipeline includes `.github/workflows/init-dependencies.gradle` to resolve runtime resource themes (`Theme.Material3`) during assembly without altering existing source code or `app/build.gradle`.
- **Artifact Retention**: Uploaded APK artifacts are retained on GitHub for 30 days.
